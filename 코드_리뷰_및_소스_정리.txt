코드 리뷰 및 소스 기능/역할 정리
대상: 미니피드 앱 (MP1, MP2) + 할일 앱 (MP1)
작성일: 2026-11-11
검토 방식: 전체 소스를 읽고 검토. tsc 타입 검사는 미니피드 MP2만 실행.

====================================================================
1. 공통 구조
====================================================================
세 앱 모두 같은 틀: Expo Router 기반. 화면 내용은 features/, 공통 UI는 shared/.
src/app/ 안의 라우트 파일은 "export { default } from ..." 한 줄로 화면을 연결할 뿐임.

[파일] [역할] [세 앱 동일 여부]
- shared/theme.ts            : 색/폰트/간격/모서리 디자인 토큰                 (동일)
- shared/ui/AppText.tsx      : 폰트/굵기를 디자인에 맞춰주는 Text 래퍼          (동일)
- shared/ui/Button.tsx       : primary/soft/ghost 버튼, loading 중 눌림 차단     (동일)
- shared/ui/IconBadge.tsx    : 동그란 배경 안에 아이콘                          (동일)
- shared/ui/Screen.tsx       : 화면 바깥 틀 (배경색, 안전 영역)                 (동일)
- shared/ui/TopBar.tsx       : 상단바 (뒤로가기, 제목, 부제, 오른쪽 슬롯)        (동일)
- shared/ui/index.ts         : UI 한곳에서 내보내기                             (동일)
- shared/ui/Icon.tsx         : lucide 아이콘 이름 -> 컴포넌트 연결              (다름: 앱마다 쓰는 아이콘 다름, 할일 앱은 strokeWidth 추가)
- shared/ui/StateViews.tsx   : 빈 상태 안내 EmptyState                          (다름: 할일 앱은 title/icon/testID 추가)
- app/_layout.tsx            : 폰트 5종 로딩 후 스플래시 숨김, Provider 감싸기, Stack 설정 (거의 동일)

2. 미니피드 MP1 (서버 없음)
====================================================================
- features/posts/types.ts                    : Post 타입 (id, nickname, content, createdAt)
- features/posts/seed.ts                     : 처음 보이는 예시 글 4개 (minutesAgo로 시각 생성)
- features/posts/PostsProvider.tsx           : 글 목록을 메모리에 저장하는 Context. addPost는 맨 앞에 추가, getPost는 id 조회. 작성자는 MY_NICKNAME 고정
- features/posts/screens/FeedScreen.tsx      : 글 목록(FlatList). 카드 -> 상세, 연필 버튼 -> 글쓰기. 새 글이 생기면 맨 위로 스크롤
- features/posts/screens/PostDetailScreen.tsx: 글 한 개 전체 내용. 없는 id면 EmptyState
- features/posts/screens/WritePostScreen.tsx : 글 입력(최대 1000자). 빈 글이면 게시 버튼 비활성. 게시 후 router.back()
- features/posts/components/PostCard.tsx     : 아이콘 + 닉네임 + 상대 시간 + 본문 3줄 미리보기 카드
- shared/lib/time.ts                         : formatRelativeTime("5분 전"), minutesAgo, useNow(30초마다 갱신)
- app/index.tsx, post/[id].tsx, post/write.tsx: 라우트 연결. write는 _layout에서 모달로 설정

3. 미니피드 MP2 (Supabase 버전 -> 현재는 로컬로 교체됨)
====================================================================
MP1과 다른 부분만 기록.
- features/posts/types.ts                    : authorId 필드 추가
- features/posts/PostsProvider.tsx           : 원래 버전은 Supabase 익명 로그인 후 posts 테이블 조회/삽입. loading/refreshing/submitting/error 상태와 refreshPosts 제공. 현재는 메모리 방식으로 교체한 상태
- features/posts/screens/FeedScreen.tsx      : MP1에 당겨서 새로고침, 로딩 표시, 오류 배너("다시 시도") 추가
- features/posts/screens/WritePostScreen.tsx : submitting 로딩, 저장 실패 메시지, 글자 수 카운터 추가
- supabase/schema.sql                        : posts 테이블, 1~1000자 검사, 최신순 인덱스, 익명 사용자만 읽기/쓰기 RLS 정책
- shared/lib/supabase.ts                     : Supabase 클라이언트 (삭제됨)

4. 할일 앱 MP1
====================================================================

- features/todos/screens/TodoListScreen.tsx  : 입력창 + "남은 N개/완료 N개" 칩 + 목록 + 빈 상태 안내 조합

5. 리뷰
====================================================================
[좋은 점]
- 라우트/화면/컴포넌트/상태/공통 UI 분리가 깔끔함.
- 빈 입력, 이중 제출, 안전 영역, 키보드 처리가 잘 되어 있음.
- 접근성 라벨과 testID를 신경 써서 넣음.
- 할일 앱의 reducer 분리는 테스트와 저장 기능 추가에 유리한 구조.

[고치면 좋은 점]
(중간) todosReducer.ts
  reducer 안에서 Date.now()와 모듈 변수 seq++ 사용 -> 순수하지 않음. StrictMode에서 두 번 호출되면 결과가 달라질 수 있음.
  id와 시각은 addTodo에서 만들어 action에 담는 편이 안전.
(중간) 원래 MP2 WritePostScreen
  어떤 오류든 "네트워크 연결을 확인하세요"로 고정 표시.
  Provider의 addPost가 전역 error도 설정해서 글쓰기 실패 때 피드에도 오류 배너가 뜰 수 있었음.
(중간) 할일 앱
  삭제 확인/되돌리기 없음. 앱을 끄면 데이터 사라짐 (코드에 "저장은 MP2"라고 명시).
(낮음) TodosProvider.tsx
  useMemo 의존성이 [todos]뿐이라 매번 함수가 새로 생성됨. dispatch는 안정적이므로 useCallback으로 개선 가능.
(낮음) 미니피드 PostDetailScreen
  메모리에서만 글을 찾음. 로딩 중이거나 딥링크로 들어오면 "존재하지 않는 게시물"이 잠깐 보일 수 있음.
(낮음) PostCard
  눌러도 되는 카드인데 accessibilityRole 없음.
(낮음) MP1 addPost
  id가 post-${Date.now()}라서 같은 밀리초에 두 번 호출되면 충돌 (실제로는 거의 없음).
(낮음) shared/
  세 폴더에 거의 같은 코드가 복사됨. Icon, EmptyState는 이미 달라져서 수정이 어긋나기 쉬움. 제출용 분리 구조라면 허용 가능.
(정리) theme.ts
  "담당: PM", ".pen 변수와 동일" 같은 옛 프로젝트 주석이 남아 있음.

[Supabase 제거 후 MP2에 남은 흔적]
- FeedScreen의 "익명 인증 후 피드를 불러오는 중이에요." 문구 (이제 표시되지 않음)
- 새 PostsProvider의 의미 없는 loading/error 값
- types.ts의 "Supabase 익명 사용자 ID" 주석
- WritePostScreen의 네트워크 오류 문구
- .env.example, supabase/schema.sql, README의 Supabase 설명
-> 정리하면 MP1과 거의 같은 코드가 됨.
