# 프롬프트 기록 (MP3)

MP3(좋아요·댓글·신고) 작업에서 사용한 주요 프롬프트와 채택/수정 내역입니다.

## 1. 스키마 설계
- 프롬프트: "기존 posts 테이블은 그대로 두고 좋아요·댓글·신고 테이블을 추가해줘. 좋아요는 한 사람이 한 글에 한 번만, 신고는 앱에서 조회할 수 없게."
- 채택: `post_likes` 복합 기본키 `(post_id, user_id)`로 중복 방지, `post_reports`는 insert 정책만 생성.
- 수정: 처음 제안된 `unique (post_id, user_id)` 인덱스는 복합 기본키와 중복이라 제거하고 `post_likes_post_id_idx`만 남김.

## 2. 좋아요 낙관적 업데이트
- 프롬프트: "좋아요를 누르면 화면이 바로 바뀌고, 서버 저장이 실패하면 되돌려줘. 이미 눌린 상태면 에러로 보이지 않게."
- 채택: 목록 상태를 먼저 `likeCount ±1`, `likedByMe` 반전 후 insert/delete. insert 에러 코드 `23505`는 성공으로 처리.
- 수정: 실패 시 이전 값으로 되돌리고 에러 메시지를 Context `error`에 설정하도록 보완.

## 3. 상세 화면 개편
- 프롬프트: "상세 화면에 좋아요·댓글 목록·하단 고정 입력창을 넣고, 상단에 신고 버튼을 달아줘."
- 채택: 진입 시 `refreshPost` + `fetchComments`, `KeyboardAvoidingView` 안에 ScrollView + 하단 입력창.
- 수정: 댓글 목록은 별도 FlatList 대신 ScrollView 안 map으로 처리(게시글 본문과 한 스크롤로 묶기 위해).

## 4. 신고 모달
- 프롬프트: "신고 사유 5개 라디오 + 선택 설명 300자, 사유 없으면 버튼 비활성, 성공하면 안내."
- 채택: `Modal` 2개(입력용·완료 안내용), 사유 미선택 시 `disabled`, 실패 시 모달 안에 에러 문구.
- 수정: 완료 안내는 모달을 닫은 뒤 별도 안내 모달로 표시해 "신고가 접수되었습니다" 문구가 확실히 보이게 함.
