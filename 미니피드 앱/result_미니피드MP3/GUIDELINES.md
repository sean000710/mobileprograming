# 잼타 운영 가이드라인

익명 게시판이기 때문에 "누가 썼는지"보다 "무엇이 문제인지"를 기준으로 판단합니다. 아래 기준은 신고 처리와 데이터 노출 범위에 대한 약속입니다.

## 금지 콘텐츠

| 유형 | 예시 |
| --- | --- |
| 스팸·광고 | 상업적 홍보, 반복 도배, 외부 링크 유도 |
| 욕설·비방 | 특정인을 향한 모욕, 비하, 허위 사실 유포 |
| 성적 콘텐츠 | 성적 표현, 음란물, 성적 대상화 |
| 불법 정보 | 불법 거래, 도박, 마약, 저작권 침해 |
| 개인정보 노출 | 실명·연락처·주소·계좌 등 타인의 개인정보 게시 |
| 사칭 | 운영자·타인·기관을 사칭하는 글 |

## 신고 처리 원칙

**사유 판단 기준** — 신고 사유는 앱에서 5가지(`spam`, `abuse`, `sexual`, `illegal`, `other`)로 접수됩니다. 본문과 추가 설명을 함께 읽고, 표현 자체가 기준을 넘었는지와 맥락(대화 흐름, 반복 여부)을 함께 봅니다. 판단이 어려우면 `other`로 접수된 건을 우선 검토합니다.

**조치 3단계**
1. **확인**: 신고 접수 후 24시간 안에 해당 글과 신고 사유를 검토합니다.
2. **조치**: 기준 위반이면 게시글 비공개 또는 삭제, 반복 위반이면 작성자(익명 사용자) 차단을 검토합니다.
3. **기록**: 조치 결과와 사유를 내부에 남기고, 같은 사용자의 반복 신고는 누적해서 봅니다.

**신고자 보호** — 신고자 정보는 앱에 노출되지 않고 운영자만 확인합니다. 신고를 이유로 신고자에게 불이익을 주지 않으며, 신고 내용을 피신고자에게 그대로 전달하지 않습니다.

## 상호작용 데이터 노출 범위와 이유

- **좋아요 집계 수와 내 하트 상태**는 피드와 상세 화면에 보입니다. 참여자 명단을 화면에 표시하지 않는 이유는 사용자 간 추적이나 보복을 줄이기 위해서입니다. 현재 DB 정책에서는 익명 인증을 마친 앱이 글별 좋아요 행의 `user_id`를 읽을 수 있습니다. 앱은 이 익명 ID들로 집계 수와 내 하트 상태를 계산합니다.
- **신고 내역**의 사유·설명·신고자 ID는 권한이 있는 운영자가 서버에서 열람합니다. 신고자를 보호하고 보복을 막기 위해 익명 사용자의 앱 권한은 신고 등록으로 제한합니다. 신고자는 앱에서 접수 완료 안내를 받습니다.
- **댓글 작성자**: 닉네임은 익명 사용자 ID 앞 4자리에서 파생한 `익명 XXXX` 형태로만 표시합니다. 실제 사용자 ID나 개인 식별 정보는 화면에 나오지 않습니다.

민감한 개인정보(실명, 연락처, 위치 등)는 수집하지 않으며, 신고 처리 과정에서도 필요한 최소 정보만 다룹니다.
