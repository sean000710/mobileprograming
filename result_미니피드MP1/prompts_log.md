# 바이브 코딩 프롬프트 로그

- 사용 도구: Claude Code (Anthropic) — 터미널 기반 AI 코딩 에이전트. 코드 작성·수정, 에뮬레이터 실행 및 화면 캡처 확인까지 AI가 직접 수행함.
- 대상: 잼타(JamSNS) 게시글 피드 앱 (React Native / Expo)
- 아래는 한 번의 작업 세션에서 오간 주요 프롬프트와, AI 응답을 **채택 / 수정 / 되돌린** 내역입니다. 프롬프트 원문은 따옴표로 표시했고, 길어서 줄인 곳은 `…`로 표시했습니다.

## 1. 프로젝트 파악

**프롬프트** — "지금 기획 구조 기술 스택 다시한번 말해줘"

**AI 응답** — 저장소의 `README.md`, `docs/DB_SCHEMA.md`, 테스트 케이스 문서를 읽고 기획(학교 기반 학생 SNS, 게시판 3종, 신고·쪽지 등)과 DB 구조를 요약. 기술 스택은 문서에 기록이 없고, 기술 보고서 PDF는 환경 문제로 읽지 못했다고 밝힘.

**채택/수정** — 기획·구조 요약은 채택. 기술 스택은 AI가 추측하지 않고 "기록 없음"이라 답했으므로, 이후 사용자가 직접 스택을 정함(React Native + Expo).

## 2. 기술 스택 타당성과 개발 환경

**프롬프트** — "일단은 지금 리액트 네이티브로 프론트 구조 만들고 슈퍼베이스 하고 파이썬으로 백엔드 구성하려고 하는데 이렇게만 해도 이 구조를 완성하고 잘 돌릴 수 있을까? 추가로 내가 리엑트 작업해본적이 없어서 Expo하고 뭐하고 이런 환경이 필요하던데 어떤 환경들이 필요하고 내가 부족한 환경은 무어야ㅑ"

**AI 응답** — 가능하다고 답하며 Supabase(DB·로그인)와 Python(제한·필터 등 서버 로직)의 역할 분담을 제안. PC에서 직접 명령을 실행해 Node, Git, Python, JDK, Android SDK는 이미 설치돼 있고 Supabase·Expo 계정 등이 부족하다고 진단.

**채택/수정** — React Native + Expo는 **채택**. Supabase·Python 백엔드는 이후 과제 범위(서버 없는 피드)에 맞춰 **제외**함.

## 3. 팀 작업 방식

**프롬프트** — "그러면 이게 팀작업이고 나머지 팀원들이 이런 공공 프로젝트 작업에 대한 경험이 전무한 사람들이라 내가 좀 pm처럼 진행을 해야할거 같아서. 우리가 먼저 일단 프론트 구조를 싹 만들어두면 각 팀원들에게 …(중략)… 이렇게 기능별로 작업지시를 할까 하는데 어떨거같아? 아님 이렇게 하면 오히려 힘들어지나?"

**AI 응답** — 뼈대를 먼저 만들고 기능 단위(화면+서버 연결을 한 사람이)로 나누는 방식을 권장하고, 피해야 할 경우(뼈대를 너무 오래 만들기, "서버 연결 담당"을 따로 두기, 한 파일을 여러 명이 수정하기)를 안내.

**채택/수정** — 기능별 폴더로 나누는 구조 방식은 **채택**(`features/` 폴더 구조의 근거가 됨).

## 4. 디자인 파일(.pen)에서 기능 목록 추출

**프롬프트** — "jamSNS.pen파일 읽고 어떤 기능들 우리가 만들어야했는지 쭉 정리해줄래?" → (Pencil 앱을 켠 뒤) "지금 .pen파일 켰으니까 다시 한번 검토하면서 나열해줘"

**AI 응답** — 처음에는 Pencil 앱에 연결되지 못해 기존 분석 문서를 근거로 정리하면서 "`.pen`을 직접 읽지 못했다"고 명시. 사용자가 앱을 켠 뒤에는 모든 화면의 텍스트를 직접 읽어 기능 목록(A~J, 난이도 표시)을 작성하고 `docs/JamSNS_기능_목록.txt`로 저장.

**채택/수정** — 문서 기반 1차 답변은 직접 확인 후 **재검증**되어 대체됨. 직접 읽은 결과는 **채택**.

## 5. 프론트 뼈대 생성 → UI를 디자인에 정확히 맞추기

**프롬프트 (뼈대)** — "…우리가 뼈대, 프론트 구조를 만들어두면 팀원들에게 각각의 기능들을 나눠주고 구현해서 붙여주는 식으로 팀프로젝트를 진행해보려고 해."

**AI 응답** — Expo 프로젝트 생성, 기능별 폴더, 공통 UI 부품, 더미 데이터 API, README 작성. 에뮬레이터에서 실행해 확인.

**프롬프트 (검증)** — "그 혹시 pen파일 잘 읽어서 프론트ui만 만든거 맞니?"

**AI 응답** — 솔직하게 "디자인 색상·문구와 일부 화면 캡처만 반영했고 나머지 화면은 레이아웃을 AI가 임의로 정했다"고 인정.

**프롬프트 (수정 요청)** — "…먼저 구조를 파악해주고 ui는 완전히 pen파일을 참고해서 만들어지면 좋겠어. 그리고 ui말고는 아직 빈 기능인거지? 구조상으로 팀원들이 각 기능들을 갖다 붙이기 좋은 구조인지도 한번 봐줘"

**AI 응답** — `.pen`의 모든 화면 노드(여백, 둥글기, 폰트 크기·굵기, 색, 그라디언트, 아이콘)를 읽어 UI를 전부 다시 작성하고, 에뮬레이터에서 화면마다 `.pen`과 비교해 확인. 서버에 연결된 것은 로그인뿐이고 나머지는 더미 데이터라고 답변.

**채택/수정** — 재작성한 UI는 **채택**. 검증 과정에서 AI가 스스로 발견해 **수정한 문제**:
- 로그인 직후 게시판 선택을 건너뛰고 홈으로 가던 버그
- 로그아웃 후 "Unmatched Route" 오류
- 모달 배경이 안드로이드 상태바 영역을 덮지 못하던 문제
- 안드로이드 글자 위아래 기본 여백 때문에 디자인보다 간격이 넓던 문제
- React Native 0.88에서 `ScrollView` ref 타입이 바뀌어 발생한 타입 오류

## 6. AI 답변 정정 요청

**프롬프트** — "그 로그인은 서버와 연결되어있다 했는데 난 supabase 세팅한적이 없는데 어떻게 연결했어? 이게 뭔가 어디 노트북에서 서버를 열고 해야 쓸 수 있는게 아니라 그냥 갖다 쓸 수 있는 상시 서버가 있어?"

**AI 응답** — "연결한 게 아니라 **연결 코드만 준비**한 상태이며 접속 주소·키(`.env`)가 없어 실제로는 목업 모드였다"고 표현이 부정확했음을 정정. Supabase가 클라우드 서비스라 계정만 만들면 상시 서버로 쓸 수 있다고 설명.

**채택/수정** — AI의 정정을 **수용**. 이후 로그인을 제거하고(7번) 서버 연동 없이 더미 데이터로 진행함.

## 7. 기능 축소 (로그인·탭바 등 제거)

**프롬프트** — "지금 구조에서 로그인 지우고 그냥 딱 켜면 게시물화면부터 나오게 해줘. 인기 게시물 항목도 지우고 탭바도 다 지워 개인 페이지도"

**AI 응답** — 되돌릴 수 있도록 삭제 전에 `src/`를 백업한 뒤 로그인·가입, 인기 게시물, 하단 탭바, 마이페이지를 제거. 앱을 켜면 바로 피드가 나오도록 수정하고 에뮬레이터로 동작 확인.

**채택/수정** — **채택**.

## 8. 과제 요구 기능만 남기고 파일 정리

**프롬프트** — (과제 요구 기능 붙여넣기) "게시글 카드(닉네임·작성 시각·내용)로 구성된 스크롤 피드를 구현하기 / 글쓰기 화면에서 작성한 글이 피드 최상단에 추가되게 하기 / 게시글 탭 시 상세 화면으로 이동하기 / 작성 시각을 '5분 전' 같은 상대 시간으로 표시하기" + "이 기능만 뚜렷하게 구현되고 파일 정리 되도록(게시판 선택부분도 삭제해도 될듯)"

**AI 응답** — 게시글 기능을 `features/posts/` 한 폴더로 합치고(저장소 Context, 예시 글, 카드, 피드·상세·글쓰기 화면), 상대 시간 함수와 30초 자동 갱신 훅을 작성. 게시판 선택·신고·쪽지·채팅·캘린더 등 불필요한 파일과 안 쓰는 패키지 4개를 제거해 `src` 파일을 약 60개에서 21개로 정리. 에뮬레이터에서 글쓰기 → 최상단 추가 → 상세 이동을 직접 눌러 확인.

**채택/수정** — **채택**. AI가 내린 판단 중 확인한 부분:
- 요구 범위 밖인 제목·사진·좋아요·댓글은 제거
- 로그인이 없으므로 새 글 작성자는 고정 닉네임 `열정만점잼타`로 처리
- 서버가 없어 앱을 완전히 종료하면 새 글이 사라지는 한계를 README에 명시

**프롬프트** — "파일 구조 망쳐도 되니까 …(제출 폴더 구조: app/, README.md, screenshots/, prompts_log.md)… 이구조로 정리해서 만들 수 있어? 힘들면 아예 복사해서 새 폴더에 구성해도 됨"

**AI 응답** — 원본은 그대로 두고 새 폴더에 제출 구조를 구성. 복사본에서 `npm ci` → 타입 검사 → 린트를 통과시키고, 복사본으로 앱을 직접 실행해 스크린샷 4장(피드, 글쓰기, 글쓰기 후 피드, 상세)을 촬영. README와 이 로그를 작성한 뒤 ZIP으로 묶음.

**채택/수정** — **채택**.

## 정리: AI 결과물을 그대로 쓰지 않고 바꾼 판단들

| 상황 | 판단 |
|---|---|
| AI가 처음 만든 UI가 디자인과 달랐음 | 사용자가 직접 질문해 확인 → 전부 다시 작성하게 함 |
| AI가 "서버에 연결됨"이라고 표현 | 사실과 달라 정정을 요구 → 서버 없는 더미 데이터 방식으로 확정 |
| AI가 제안한 Supabase·Python 구성 | 과제 요구 기능(서버 없는 피드)에 포함되지 않아 제외 |
| 기능이 과제 요구보다 많았음 | 요구한 4가지 기능만 남기고 나머지 삭제 |
