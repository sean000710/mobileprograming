# 바이브 코딩 프롬프트 로그

- 사용 도구: OpenAI Codex
- 대상: React Native(Expo) 게시글 피드 앱
- 단계: MP1 메모리 피드를 Supabase 공용 피드로 전환

AI가 생성한 결과는 과제 요구사항과 기존 프로젝트 구조를 기준으로 검토하고, 범위를 벗어난 기능은 제외했습니다.

## 1. 과제 범위 확인

**사용자 프롬프트 요약**

> Firebase 또는 Supabase에 게시글을 저장하고, 두 에뮬레이터에서 같은 피드가 보이는 것을 확인한다. 익명 인증만 사용하고, 당겨서 새로고침과 작성 실패 안내를 구현한다.

**AI 제안**

- 기존 JAMTA 기술 스택과 연결되는 Supabase 사용
- 익명 인증, `posts` 테이블, RLS, 새로고침, 실패 안내 구현
- Firebase FCM, FastAPI, AI 검열 등 기존 프로젝트의 추가 기능 제외

**채택/수정 내역**

- Supabase 선택과 기본 데이터 구조는 채택했습니다.
- 실시간 구독은 요구사항이 아니므로 제외하고, `RefreshControl`을 사용한 수동 새로고침으로 수정했습니다.

## 2. 기능 최소화

**사용자 프롬프트**

> 앞에 우리가 했던 특별한 내용은 싹 날리고 기본만 하면 된대.

**AI 응답 요약**

- 회원가입 화면, 학교 구분, 프로필, 이미지, 댓글, 좋아요, 알림, FastAPI, OpenAI 검열을 제외
- 텍스트 게시글 작성·조회와 익명 인증만 유지

**채택/수정 내역**

- 과제 평가 기준에 없는 기능은 모두 제외했습니다.
- 기존 MP1 화면 구성은 유지하되 상단 제목을 학교 게시판에서 `모두의 피드`로 변경했습니다.

## 3. 개인 과제 여부 판단

**사용자 프롬프트**

> 이게 따로따로 평가하는 것 같아.

**AI 응답 요약**

- 개인별 MP1 프로젝트를 이어서 작업하고 각자 ZIP을 제출하는 구조로 판단
- 기기 A·B는 팀원 두 명이 아니라 한 사람이 실행하는 에뮬레이터 두 대라고 정리

**채택/수정 내역**

- 팀 기능 분담 방식 대신 개인 제출 기준으로 개발 범위를 확정했습니다.

## 4. 기존 MP1 프로젝트 분석

**사용자 프롬프트**

> 이거야. (`result.zip` 첨부)

**AI 분석 결과**

- Expo Router와 TypeScript 사용
- `PostsProvider`의 React Context에 게시글을 메모리로만 저장
- 피드, 글쓰기, 상세 화면이 이미 구현됨
- 서버 연결 코드와 환경변수 파일은 없음

**채택/수정 내역**

- 기존 화면과 라우팅은 유지했습니다.
- 메모리 저장을 Supabase 조회·INSERT 방식으로 교체했습니다.
- 기존 MP1 더미 데이터는 서버 동기화 평가에 혼동을 줄 수 있어 사용하지 않도록 했습니다.

## 5. Supabase 구현

**AI 구현 제안**

- 앱 시작 시 저장된 세션을 확인하고, 없으면 `signInAnonymously()` 실행
- `author_id`에 `auth.uid()` 저장
- 모든 익명 사용자가 글을 읽고 본인 UUID로만 글을 작성하도록 RLS 적용
- AsyncStorage에 세션 저장
- 환경변수가 없을 때 설정 안내 표시

**채택/수정 내역**

- 제안한 익명 인증과 RLS 정책을 채택했습니다.
- 실제 UUID 전체를 화면에 표시하지 않고 앞 4자리만 익명 표시명에 사용했습니다.
- 클라이언트에는 Publishable Key만 사용하고 `service_role` 키는 사용하지 않았습니다.

## 6. 새로고침과 오류 처리

**AI 구현 제안**

- 피드에 `RefreshControl` 연결
- 조회 실패 시 피드 상단에 오류와 다시 시도 버튼 표시
- 작성 실패 시 글쓰기 화면에 오류 표시
- 저장 중 게시 버튼을 비활성화해 중복 등록 방지

**채택/수정 내역**

- 전체 제안을 채택했습니다.
- 저장 성공한 경우에만 글쓰기 화면을 닫도록 처리했습니다.
- 실패 시 입력 내용을 유지해 사용자가 다시 시도할 수 있도록 했습니다.

**AI 작업**

- Supabase 선택 이유와 설정 절차를 README에 작성

- 에뮬레이터 A 작성 화면 촬영
- 에뮬레이터 B 새로고침 화면 촬영
- Supabase `posts` 테이블 화면 촬영
