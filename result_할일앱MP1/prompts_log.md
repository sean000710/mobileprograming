## 1. 과제 요구사항 분석

**프롬프트**: "고급모바일 수업을 듣고 있는데 첫번째 과제제출역할을 맡았어 … 1단계 — 할 일 앱 화면 만들기 … 제출 산출물 app/ README.md screenshots/ prompts_log.md"

**AI 응답**
- 통과 기준 4가지(추가와 완료 토글, 빈 상태 안내, README의 실행 절차와 기능 목록, 민감정보 없음)와 ZIP 최상위 구조를 정리했습니다.
- 인메모리 상태만 쓰면 되고, AsyncStorage 같은 기기 저장은 MP2 범위라고 판단했습니다.
- 팀 테스트 보고서에서 선정한 스택(React Native + TypeScript)으로 진행하자고 제안했습니다.

**채택/수정**: **채택**. 저장 기능은 일부러 넣지 않았습니다.

## 2. 팀 디자인 파일 반영

**프롬프트**: "(JamSNS.pen 첨부) 자 이거까지 해서 분석 시작하고 …"

**AI 응답**: `.pen` 파일의 변수(primary `#2563EB`, bg `#F5F8FF`, border `#DCE3F0` 등)와 게시물 카드 스타일(모서리 16, 1px 테두리, 패딩 16)을 추출했습니다. 처음에는 그라데이션 헤더와 시스템 폰트를 쓰는 독립 Expo 프로젝트를 작성했습니다.

**채택/수정**: 색상과 카드 스타일은 **채택**. 독립 프로젝트 구조는 4번에서 **되돌림**.

**프롬프트**: "(github 매뉴얼 붙여넣기) 고모프 프로젝트 협업 규칙 … main / develop / feature/*"

## 4. 팀 저장소 구조에 맞춰 다시 작성

**프롬프트**: "https://github.com/sean000710/mobileprograming 우리 깃허브 사이트야 접근돼? 접근되면 다 봐봐"

**AI 응답**: 저장소를 확인한 결과, 팀이 이미 과제별 폴더(`result_미니피드MP1/`, `MP2/`), Expo SDK 58, Expo Router, 공통 UI 부품(`shared/ui`), Jua와 Noto Sans KR 폰트, lucide 아이콘을 쓰고 있었습니다. 그래서 2번의 독립 프로젝트를 버리고 다음과 같이 다시 작성할 것을 제안했습니다.
- 미니피드 MP1의 `app/` 뼈대(package.json, lockfile, app.json, shared)를 그대로 재사용
- `features/posts`를 `features/todos`로 교체 (Provider, reducer, components, screens 구조 동일)
- 폴더 이름은 팀 규칙에 맞춰 `result_할일앱MP1/`

**채택/수정**: **채택**. 팀원들이 이미 아는 구조이고 패키지 버전도 같아서 설치 문제가 적습니다.
- 공통 `EmptyState`에 제목과 아이콘 배지를 추가했습니다. 기존 화면은 `message`만 넘기므로, 미니피드에 다시 쓸 때는 `title`을 넘기도록 맞춰야 합니다.
- `Icon`에 check, plus, trash, clipboard-list 아이콘을 추가했습니다.

## 5. 상태 관리와 예외 처리

**프롬프트**: "목록·추가·완료 토글을 인메모리로 구현하고, MP2에서 저장 붙이기 쉽게"

**AI 응답**
- `useReducer`와 순수 함수 `todosReducer`(add / toggle / remove)로 구현하고, Context(`TodosProvider`)로 화면에 제공했습니다.
- 공백만 입력한 경우 무시하고 `+` 버튼을 비활성화했습니다. 입력은 최대 50자로 제한하고, 새 항목은 맨 위에 추가되도록 했습니다.
- `FlatList`의 `ListEmptyComponent`로 빈 상태 안내를 표시했습니다.
- 팀이 E2E 테스트 도구로 Maestro를 선정했으므로 `testID`(todo-input, todo-add-button, todo-list, empty-state)를 넣었습니다.

**채택/수정**: **채택**. 예시(더미) 데이터는 넣지 않고 빈 목록으로 시작하게 해서, 첫 화면에서 빈 상태를 바로 확인할 수 있게 했습니다.

- `todosReducer`를 직접 실행해 다음을 확인했습니다: 공백 입력 무시, 최신 항목 맨 위 추가, 토글 on/off, 50자 제한, 삭제
- 모든 `.ts`/`.tsx` 파일의 문법을 검사해 오류 0건을 확인했습니다.
- 웹 브라우저(Chrome 개발자 도구의 모바일 화면 모드, iPhone 12 Pro 크기)에서 실행해 빈 상태 → 추가 → 목록 → 완료 → 삭제 흐름을 확인하고 스크린샷 4장을 촬영했습니다. (아이폰 Expo Go에서 QR 인식이 되지 않아 웹으로 확인함)
